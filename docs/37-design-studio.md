# 设计工作室：独立应用验证

应用版本 0.3.0，要求 SDK >=0.0.6。业务源码在 apps/design-studio，独立静态 UI，通过公开 `@sitoo/sdk/ui` 调用平台，不导入 Desktop IPC、Pi、账户凭据或上游网络客户端。

0.1.2 区分生图与保存占位文案；共享 Desktop 保存链路兼容二进制响应头并验证图片内容，不重新生图。

0.2.0 新增通用附件 SDK 的两阶段参考图、逐图说明和草稿恢复，不增加设计专用平台 API。

0.3.0 新增直接生图和设计方案双模式，重做左右工作区与响应式布局，高级参数、核验清单和历史默认折叠。资源包 1.1.0 增加六个结构化设计方向与布局示意，只把选定方向的相关规范注入方案。SDK 仍为 0.0.6，没有增加应用专用公共接口。

## 使用流程

0.1.1 新增输出预算选择，默认 8192 Token。预算限制包括上游可能计入的推理消耗，不能提前保证内容足够。明确截断时可展开查看已有内容，调整预算后主动重新生成完整方案（可能计费），不自动续写或拼接 JSON。历史 unknown 任务不补造诊断信息。

1. Desktop 登录账户，在设置中启用至少一个兼容平台文本模型，配置共享图像生成能力与作品目录。
2. 应用市场加载已构建的设计工作室开发包，核对文本推理和生图权限后安装。正式分发仍经签名市场；本版不自动上架到生产市场。
3. 打开应用，新草稿默认“直接生图”：输入提示词、画幅和分辨率，点击“生成图片”。不调用方案推理，不注入资源包规则；无附件时提示词原文保持不变。上传图片后，平台将逐图说明随参考图片发送。文本模型目录不可用不会阻断直接生图。
4. 需要设计帮助时切换“设计方案”，选择“海报与文化传播”或“商品与品牌传播”，填写用途、受众、文字、风格与约束。可以选择具体方向，也可“不限定方向”。“方案模型与高级设置”中选择已启用的文本模型及预算；使用参考图时需支持看图。
5. 生成设计方案，右侧查看构图、配色、假设与人工检查清单，修改最终提示词。按方案生成图片时携带同一组参考图与说明。额外 HTTPS 链接只用于生图。方案模型和生图模型分别配置；文本推理可能计费。
6. 两种模式沿用 Desktop 三模式审批；原任务卡片随排队、生成、保存与完成状态更新。保存期间不提示“正在生图”。生成成功后平台自动保存到作品，点击图片或下载按钮下载副本。预览读取失败可重新加载预览，不重新生图。
7. 两种模式保留各自文本输入，共用图片、说明、画幅、分辨率和生图链接。切换模式不取消任务。方案运行时共享输入暂不可修改，仍可切到直接生图输入独立提示词。保存草稿后可重开；旧版草稿保留设计模式。进行中的文本任务按同一 requestId 查询，生图通过平台任务列表恢复。失败与未知结果保留诊断，不自动再收费，不作为成功作品。

资源包、设计方向、需求、参考图及说明、画幅变化会清除当前方案；切换模式不会。重开时资源包版本变化也会清除旧方案，保留需求并提示重新形成方案；不会更改已发起任务。方案检查清单供人工审阅，不代表自动审美验收。当前一个应用草稿、多个生图历史任务；不提供完整多项目管理。空闲时不持续查询生图任务，进行中的任务采用串行查询；连续三次失败或等待十分钟后暂停自动查询，提示刷新原任务。手动刷新查询图片列表及当前方案任务，不重新生成。

## 资源内容与开发边界

每个行业包包含 `rules` 文本与 `catalog` JSON。后者作为现有 `style` 资源声明，经 `resources.read(packId, 'catalog')` 读取并核验文件摘要，没有改变 SDK 资源包契约。`schemaVersion: 1` 的案例字段为 id/name/summary/tags/suitable/layout/style/palette/avoid/preview；应用解析器检查标识唯一、文本限制、配色及示意类型，构建时也执行校验。按需求中的标签匹配排序，用户决定方向；没有使用向量数据库或自动付费生成候选。

六个方向分别为叙事主视觉、展览信息编排、文字与图形表达、产品聚焦、发布与倒计时、活动信息分区。布局示意由应用本地绘制，明确标注“布局示意”；不是图片模型参考图，不作为成品效果保证。JSON 规范由 Sitoo 编写，许可见 `resources/sitoo-design-LICENSE.txt`；行业规则沿用并注明原来源。

目前实现的是内容标准与案例选择的第一版。尚未完成成品案例盲评、独立资源包安装、品牌原图管理、参考图结构化分析节点或精确文字模板合成。完整后续计划见[资源包架构提案](./38-design-resource-pack-architecture.md)，不能把规划中的能力视为本版公共 API。

## 独立构建与打包

```powershell
node apps/design-studio/build.mjs
node scripts/app-toolkit.mjs
node release/developer-kit/sitoo-app.mjs pack apps/design-studio release/apps/sitoo-design-0.3.0.spkg
node release/developer-kit/sitoo-app.mjs check release/apps/sitoo-design-0.3.0.spkg
```

源码构建使用 React、Base UI Button 与 assistant-ui 开源 ImageGeneration/surfaces 组件，保持品牌色、留白与阅读层级。工作区可复用已安装构建依赖；外部开发者安装开发工具包中的 SDK，并将 package.json 的 workspace 依赖改为实际本地 SDK 安装路径，再安装其声明的前端依赖。不要求其他应用使用同一前端框架。

应用 build 生成静态 payload 和契约配置；标准打包器只打包 payload，逐项校验摘要。资源包规则参考 poster-generator-skill 的层级/排版/检查方法，保留 MIT 声明，不执行原项目 Skill 或其重试流程；资源不获得平台权限。

## 双入口与当前边界

`@设计工作室 help` 或 `@设计工作室 帮助` 返回本地说明。显式 propose / generate 使用同一平台能力；propose 的 model 需使用 SDK 模型列表中的标识，generate 需提供最终提示词。当前对话不会自动组合完整行业方案流程，应用端的规则组装属于业务代码；自然语言编排仍是平台后续缺口。

随包资源的版本和内容摘要会核验，可在 UI 切换；没有独立在线资源包安装市场。上传 PNG/JPEG/WebP 原图，每张 <=12 MiB、<=2400 万像素，最多 8 张（含生图额外链接）。平台标准化为 <=1 MiB 的 PNG 副本，原图不改写。图片和说明会进入模型请求；草稿保存附件 ID/说明，重开可恢复。移除只删除草稿引用，平台每账户每应用最多 200 个附件，当前无删除回收 API。参考图不保证 Logo 精确复制，尚无后期精确叠加能力。没有印刷级 CMYK、出血、字体嵌入保证。真实付费通道与设计质量仍需用户在审批后验收，模拟测试只能证明桥、任务和存储行为。
