# 平台概览

OpenSitoo 为应用提供运行界面、任务管理和已授权的平台服务。你可以开发一个独立界面的应用，也可以把业务逻辑做成共享能力，让多个应用或对话入口使用同一实现。

本页帮助你选择开发方式，并理解应用与宿主各自负责什么。阅读本页无需先安装 SDK；动手前请完成[环境与工具](setup)中的准备。

## 用一个例子理解三个角色

假设你开发了两个文本工具：一个用于整理笔记，一个用于编辑文案。两个工具都需要去掉多余空格、统一文本格式。你可以把这段逻辑放在一个共享的“文本标准化”能力中。

| 角色 | 在这个例子中是什么 | 主要负责什么 |
| --- | --- | --- |
| 应用 | 笔记工具、文案工具 | 提供界面，收集输入，调用能力并展示任务/结果 |
| 能力 | 文本标准化实现 | 声明可接受的输入和输出，执行具体业务逻辑；可以独立版本化 |
| 宿主 | 运行应用和能力的可信环境 | 核验身份、安装与权限，建立允许的调用关系，执行任务和提供结果查询 |

“契约”指调用双方共同遵循的输入、输出和行为约定，例如标准化能力接收文本并返回处理后的文本。“SDK”是帮助程序使用这些契约的开发库；它不替应用取得授权。精确字段见[应用契约与命令](/guides/contracts)及[请求与响应协议](/capabilities/protocol)。

这个例子说明职责关系，不是一套可直接运行的代码。实际创建、构建和调用请按[第一个共享应用](quickstart)操作。

## 选择适合你的开发方式

| 方式 | 适合什么目标 | 使用什么 | 从哪里动手 |
| --- | --- | --- | --- |
| 静态应用 | 开发 HTML/CSS/JavaScript 界面，使用已开放的文本、图片、配置、草稿和资源接口 | App 开发工具包、应用页面 SDK | [第一个静态应用](static-app) |
| 独立应用与共享能力 | 多应用复用业务逻辑，页面与对话消费同一能力，分别维护应用与能力版本 | 共享能力开发工具包、能力包管理工具、能力 SDK | [第一个共享应用](quickstart) |
| 可信宿主集成 | 为已声明环境接入服务、安装、授权、执行和持久化 | Node.js 可信宿主接口；需要宿主操作者权限 | [SDK 与 API 导航](/reference/) |

两种应用开发方式可以各自满足不同目标；选择共享能力不等于自动拥有平台文本或图片服务。平台服务还需要对应契约、权限和可用的宿主配置。先从一个最小应用开始，再按实际需要组合能力。

## 应用页面 SDK 运行在哪里

应用页面 SDK 是给应用界面使用的 JavaScript 接口。静态应用通过 OpenSitoo 提供的隔离页面与宿主通信；共享能力页面通过宿主提供的受限任务桥或明确的开发传输调用能力。

Chrome、Edge 等浏览器可以显示网页，但不会自带 OpenSitoo 的身份、授权或任务桥。仅双击 HTML 文件不能让应用拥有平台 API。开发宿主能提供本机页面容器，用于声明支持的开发流程；它不等于一个完整的生产 Web 客户端。

接入静态应用请看[应用页面 SDK](/guides/browser-client)；共享能力页面请看[独立页面](/capabilities/pages)。两者的初始化和运行前置条件不同，不应直接互换代码。

## 一次能力调用如何完成

下面是共享能力的职责流程，具体请求及字段以接口参考为准。

1. **应用准备输入和请求标识。** requestId 是调用者在提交前生成并保存的请求标识，用来关联同一次业务请求。
2. **宿主检查调用资格。** 校验当前消费应用/入口、已安装能力与绑定、权限和参数；应用不能在请求中自行签发授权。
3. **宿主创建或查找原任务。** taskId 标识宿主管理的一项任务。提交被接受不一定表示业务已完成，要读取任务状态和结果。
4. **应用查询并展示结果。** 界面显示运行状态、成功结果或错误。中断后先查询原请求/任务；unknown 表示最终结果无法确认，不应换请求标识盲目重跑。

完整状态和恢复规则见[任务与恢复](/guides/tasks)。文本和图片调用可能涉及收费服务；本文的文本标准化例子没有外部模型调用，不代表所有应用调用均免费。

## 从项目到运行，谁负责哪些步骤

| 步骤 | 含义 | 负责方 |
| --- | --- | --- |
| 创建与构建 | 写契约、业务实现和界面，生成可检查的发布物 | 应用或能力开发者 |
| 检查与签名 | 核验发布物，使用可信发布者身份签名 | 持有对应发布权限和签名材料的发布者 |
| 发布与安装 | 提供发布物，将应用与所需依赖安装到目标环境 | 发布者与可信宿主操作者分别负责 |
| 入口授权 | 明确哪些应用/对话入口可以使用哪些能力及权限 | 可信宿主操作者 |
| 调用与查询 | 使用已提供的身份和授权提交业务并读取原结果 | 应用或授权的对话消费方 |

创建项目不会自动完成签名、安装、账户登录或入口授权。工具包不包含账户、令牌或私钥；这些材料的来源及保管责任必须由对应环境的可信操作者说明。普通应用不保存平台账户密钥，也不导入 Desktop 内部管理接口。详情见[入口授权](/publishing/authorization)和[签名与信任](/publishing/signatures)。
