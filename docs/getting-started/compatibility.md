## 环境与身份

Windows、Node.js 24 是当前实际验证环境。工具要求 Node >=24；其他 Node 版本或操作系统应按实际执行结果确认。应用界面可以由 Chromium 系客户端显示，本机开发宿主可提供浏览器容器；这不表示有完整生产 Web 客户端，也不构成对任意浏览器宿主的承诺。

SDK 当前以[工具下载](/downloads)中的本地目录包和页面客户端提供，未提供公共 npm 下载地址。开发客户端、测试账户、信任、公钥和入口令牌由目标环境维护者提供。你可以用[共享应用入门](quickstart)建立只属于本机的无费用测试环境，不能把它提升为生产身份。

## 支持什么，如何判断可用

| 能力 | 前置条件与边界 |
| --- | --- |
| 静态 .spkg 与应用页面 SDK | 正确安装包、有效页面会话与已声明的平台绑定 |
| 签名独立应用与共享能力 | 精确安装计划、可信签名及应用/对话分别授权 |
| 文本、图片、附件与 Agent | 检查 platform.getCapabilities()；模型列表/图片配置可用并具备相应权限；不同接口有不同费用与确认规则 |
| 配置、草稿、随包资源 | 仅自身应用/账户空间；没有任意本机文件 API |
| 持久任务与原结果查询 | 保留 requestId/taskId；unknown 不是失败，也不自动重跑 |
| Node.js 可信宿主接口 | 仅供可信操作者接线，不能交给应用页面自行注册 Provider |

features 表示接口支持，不保证模型已经配置；SDK 可导入也不代表会话有效。使用前按[应用页面指南](/guides/browser-client)检查真实能力。

## 版本兼容与更新

应用 manifest 的 sdkRange 是应用对 SDK 的兼容声明，依赖使用 semver 范围；安装和执行最终采用精确 packageId/version/sha256。应用版本、SDK 版本、协议版本、包格式版本是不同维度：当前协议和包格式为 1，不意味着 SDK 版本是 1。

范围允许新版本不等于自动安装新版本。由可信操作者检查签名、完整依赖、权限变化和活动任务后明确提交更新；旧任务保留原绑定。未知组合、失效信任或不能完成迁移时保留旧版。详见[生命周期](/publishing/lifecycle)与[数据迁移](/publishing/migrations)。

## 尚未开放的生产流程

正式组织身份、自助开发者注册与审核上架、生产密钥轮换/隔离/配额以及商业结算尚未开放。内部 Desktop IPC、完整工作台工具与第三方管理 API 不是应用公共接口。

遇到文档与发布包不一致，先确认包版本、入口和宿主配置，保留原结果和错误码，按[故障排查](/support/troubleshooting)处理。不通过关闭校验、伪造身份或换数据库绕过不兼容。
