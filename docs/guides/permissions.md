# 权限与确认

权限来自已安装应用声明和可信宿主授权，不来自页面传入的身份字段。application与conversation入口分别授权；撤销一项不会隐式授权另一项。

文本、图片和共享能力有不同确认规则：静态文本任务使用安装时授予的费用权限；图片沿用平台审批配置；签名通用服务按原任务确认计划执行。不要把它们合并成“所有调用都无需确认”或“应用可以自行批准”。

取消确认不执行。确认必须绑定原任务、修订、精确包/参数和身份；变更后旧确认失效。敏感凭据由宿主持有，配置普通字段不能存储密钥。


## 由谁执行哪一步

| 角色 | 操作 | 不应持有的内容 |
| --- | --- | --- |
| 应用作者 | 声明权限、schema 和依赖，提供用途与费用说明 | 生产账户令牌、模型密钥 |
| 用户/应用页面 | 主动发起请求、查看原任务与安全错误 | 授权管理权、签名私钥 |
| 可信操作者/宿主 | 核验发布物、授予各入口、批准原任务、绑定 Provider | 不将秘密下发给应用 |
| 规划模型 | 根据已授权工具提出参数建议 | 批准票据、任意代码执行权 |

静态应用整体权限写 manifest.permissions，每项能力也声明自己的 permissions；共享能力的 allowedEntries 约束可消费入口，真实 grants 由可信授权流程决定。仅在 schema 加一个 permission 字段不会授予权限。

操作顺序：先验签安装 → 查看精确依赖与权限 → 分别授予 application/conversation → 页面发现可用功能 → 用户提交 → 若需确认则等待可信宿主批准。安装成功不等于授权成功，工具目录可见不等于提案已批准。更新扩大权限会阻止直接提交，见[入口授权](/publishing/authorization)与[更新预检](/publishing/lifecycle)。

FORBIDDEN 时核对本账户、本应用、入口、当前授权修订、包摘要及已允许操作。拒绝后不要切换到另一个应用令牌或减少校验字段绕过。撤权后旧页面须重新连接；已经执行的业务不会因撤权自动回滚。网络和费用恢复见[任务指南](/guides/tasks)。
