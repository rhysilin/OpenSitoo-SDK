# 应用与共享能力

应用声明静态页面与依赖，共享能力声明独立业务契约与实现。共享能力可以同时被多个应用和授权的对话入口消费。

能力代码运行在受限QuickJS执行器中，只通过声明的能力代理访问宿主。不能导入Node/Electron/Pi或修改账户和授权。能力版本与应用版本独立；精确安装闭包、签名及授权共同决定一次执行。

[协议](protocol)定义请求/响应，[包格式](packages)定义发布物，[页面](pages)定义签名资源及浏览器任务桥。


## 用两个应用解释关系

应用 A 和 B 都需要规范化文本：能力包 starter-core/normalize 只实现一次业务，两个应用分别声明依赖，发布自己的页面。用户在 A 页面或 A 对话发送相同参数，都进入 A 的原任务；B 使用相同代码，但拥有自己的授权与任务。修改共享实现要发布新能力版本，应用选择依赖范围并经完整更新流程采用，不能在原版本下更改字节。

| 层 | 作者提供 | 可信宿主负责 |
| --- | --- | --- |
| 应用 | 页面、applicationId、依赖范围 | 当前安装根、页面隔离、入口身份 |
| 能力 | 输入/输出 schema、权限、Guest 函数 | 精确绑定、受限编译和执行 |
| 服务 | 接口声明包 | Provider、秘密、确认与原结果查询 |
| 任务 | 调用前保存 requestId | 去重、状态、原依赖租约与结果 |

先按[共享应用教程](/getting-started/quickstart)运行无费用例子，再读[请求协议](/capabilities/protocol)。静态 `.spkg` 使用 App SDK 页面通道；签名共享应用使用能力 SDK。两种包格式不互换，见[兼容说明](/getting-started/compatibility)。
